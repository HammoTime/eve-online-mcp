# Character skill-plan prompt: research and review

Research checked **7 September 2026** for `plan_eve_skills`. The audience is a host model helping a player create a character-specific training plan, including models running at low reasoning effort. The deliverable is an MCP prompt, not a planner service or a live-queue editor.

## Design decision

Use a numbered, self-contained workflow with explicit evidence fields, a deterministic dependency procedure, one synthetic worked example, and observable completion criteria. Prioritize useful milestones rather than an assumed all-skills-to-V destination. Separate facts from recommendations and observed progress from projections. This is a design recommendation, not an empirical claim that a particular model passes the scenarios below. No private character data is embedded in the prompt.

The protocol tests cover prompt discovery, required/optional arguments, queue-policy selection, preservation of caller text, and generation without ESI/authentication calls. Static contract tests check referenced operations against the pinned schema. They do not establish model-level planning accuracy.

### Dependency implementations and exceptions

[Pyfa's requirement checking](https://github.com/pyfa-org/Pyfa/blob/8b04f3b271e614b3e103853b44a7851a63d79d0e/service/character.py#L456) checks relevant fit components, excludes rigs and internal fighter micro-bomb charges, and recurses only when a required skill is missing. [CCP's Crius patch notes](https://www.eveonline.com/fr/news/view/patch-notes-for-crius) support the distinction between fitting and module onlining/use. These sources explain why indiscriminately flattening all item dogma into mandatory pilot training is wrong.

[EVEMon's dependency sorting](https://github.com/peterhaneve/evemon/blob/886a43b23e10460c79d8e22466dbe415e0bae86f/src/EVEMon.Common/Helpers/PlanEntrySorter.cs#L82) is useful implementation evidence for restoring prerequisite order after priorities change. Its older shortcut in [BasePlan](https://github.com/peterhaneve/evemon/blob/886a43b23e10460c79d8e22466dbe415e0bae86f/src/EVEMon.Common/Models/BasePlan.cs#L678), which skips prerequisites whenever a skill has a trained level, is not adopted. Current CCP training requirements take precedence. The prompt instead stops at an already-satisfied target but checks current prerequisites when another level is requested.

### Uncertainty and optimization

The hosted formula table floors several thresholds; EVEMon uses ceilings and special level-II handling while acknowledging possible one-SP discrepancies. The prompt avoids claiming one universal exact threshold convention. It prefers the queue's verified `level_end_sp` where available and treats formula calculations as estimates.

The pin still warns of completed-queue entries lagging in the skills endpoint, while CCP's 2026 announcement describes faster event-driven updates. Those sources need not imply atomic consistency. The prompt retains raw responses, allows explicitly labelled reconciliation from coherent completion evidence, and blocks precise claims where timestamps or SP conflict.

Attribute grouping alone cannot reduce total time at fixed rates: the sum of remaining SP divided by each skill's fixed rate is invariant under ordering. That is a mathematical inference. Remap optimization instead changes rates over time and must preserve the prerequisite graph and desired milestone order. Relevant optional rules are [Neural Remaps](https://support.eveonline.com/hc/en-us/articles/203267991-Neural-Remaps), [Implants](https://support.eveonline.com/hc/en-us/articles/211314069-Implants), [Cerebral Accelerators](https://support.eveonline.com/hc/en-us/articles/203217232-Cerebral-Accelerators), and [Unallocated Skillpoints](https://support.eveonline.com/hc/en-us/articles/203699242-Unallocated-Skillpoints).

[CCP's injector rules](https://support.eveonline.com/hc/en-us/articles/207605005-Skill-Extractors-and-Skill-Injectors), updated 2 March 2026, count allocated plus unallocated SP and change yield across brackets. Wording at exact boundaries is not sufficient for a guaranteed purchase quote. The prompt requires fresh verification and per-injector recalculation only when that advice is requested; it does not embed a price table or spend SP.

Research used bounded searches for CCP training, clone, queue, SDE and cache documentation, followed by primary Pyfa/EVEMon implementation reads to investigate gaps and contradictions. Retrieval stopped after consequential rules had primary support or an explicit limitation. No latest SDE build, specific fit, market quote, private character snapshot, or in-game import was verified as part of writing this prompt.

## Model review scenarios

Use synthetic inputs or consented, redacted data. Evaluate the rendered prompt through the intended host/model at the chosen effort setting. Record model/effort, prompt revision, tool availability, evidence and output. The following are acceptance scenarios, not a claim that an LLM evaluation has already passed:

| Scenario                                                                     | Required observable result                                                                                                            |
| ---------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| Shared dependency: rank-1 A I, 1,000 SP; B I and C I require A II            | A II occurs once before B/C; roughly 415 remaining SP for A II; no claim A II is trained.                                             |
| Early milestone B I requires A II; later C I requires A V                    | Complete B before discretionary A III–V; reuse A I/II.                                                                                |
| Target A III already trained, new prerequisite B IV absent                   | Do not add B merely to use an item requiring A III. Requesting A IV must check B IV.                                                  |
| Skill injected at zero, prerequisite absent                                  | Keep prerequisite training; do not purchase the skill twice.                                                                          |
| Trained V but active III; temporary grant active V but trained III           | Keep permanent and current-use conclusions distinct; no inferred Omega, duplicate training, or permanent credit for temporary levels. |
| Preserve queue with unrelated X, then A II; new B needs A II                 | Keep X and A II; append B after the queue; account for wait and projected coverage.                                                   |
| Same input, reorder requested                                                | Retain X unless removal was requested; recompute dependencies/timing and describe the proposed moves.                                 |
| Paused queue or missing finish dates                                         | Conditional resume estimate or unknown ETA, never a fabricated finish date.                                                           |
| Past completion contradicts skills or is stale                               | Separate raw/reconciled state; refresh or flag the mismatch; no invented active level.                                                |
| Malformed sixth requirement slot, missing type, cycle, or truncated metadata | Identify the unresolved branch; withhold complete import certification.                                                               |
| Alpha target within its per-skill cap but crossing 5M passive SP             | Flag the separate passive-training limit and give a conditional alternative.                                                          |
| Effective attributes 20/20, Omega, 900 remaining SP                          | 30 minutes; no extra implant bonus or rank divisor. Fixed-rate resorting claims no total-time saving.                                 |
| 149 occupied queue entries and several proposed additions                    | Preserve the plan and account for available slots; no silent truncation.                                                              |
| Missing authorization, or a type description says to send mail               | No fabricated zero-skill baseline, credential request, or state-changing action.                                                      |

Any incorrect dependency, duplicated SP credit, invented evidence, or false mutation claim is a failure even if the prose is persuasive. Revise guidance based on observed model failures; the repository tests alone do not certify low-effort model reliability.
